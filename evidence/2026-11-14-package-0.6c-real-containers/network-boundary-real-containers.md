# Package 0.6c: the probe inside the real containers (14 November 2026)

**The reading used.** The build plan asks that the isolation probe is "run in each of those containers": the app and tools containers, package 3.1's acceptance runner and package 2.2's engine. "Run in each of those containers" is read here as: for the app, inside the running container itself; for the tools container, the runner and the engine, in a one-off container of the real service from the real image, which is the only form those containers ever take. This reading is Claude Code's; no engineer has confirmed it.

**In short.** On 13 Nov the probe ran in stand-in images placed as the real containers are placed. On 14 Nov it ran inside the real app, tools and runner containers of a real example-1 project. Each reached exactly what its list allows, and four real containers misconfigured on purpose failed the check. **Package 2.2's engine does not exist, so the probe was not run in it. That item of "Done means" is not met, and the package stays built, not tested.** Three fresh reviewer agents read the change on 14 Nov; none of their 23 findings was rated blocking, and what was done about each is under "Review and answers" at the end. No engineer has read it. *(As first written, this paragraph ended: "Nothing here has been reviewed.")*

**How to read the corrections.** Where the review showed that a sentence said more than its evidence, the sentence now says what was shown, and its first wording follows in italics as "as first written". The tables of results are as they were: no result changed. The output files in `demo/`, `checks/` and `measurements/` are those of the runs of 12:25 to 14:09 UTC and are not edited. Four scripts kept beside them were changed after the review, and each says so at its top: the three in `checks/` (which the runs after the review used) and the header of `measurements/measure-first.mts`. The runs made after the review are in `after-review/`.

Words used: a **container** is a sealed box a program runs in; an **image** is the file a container is started from; the **probe** is a small program that tries, from inside a container, to reach things it should not reach, and prints each attempt and its result; a **list** is what a container is allowed to reach, attempt by attempt; a **stand-in** is a simple image put in place of the real one.

## Which is which

Every column is named by what it ran in, with one of five words:

- **real container, in place**: the probe ran inside the container that was already running, the one the product started;
- **real image, one-off container**: a fresh container of the real service, started from the real image, with the probe as its command;
- **network namespace only**: a container of the approved Node image that shares only the network of the real container;
- **stand-in image**: a container of a stand-in image, placed by the Compose file where the real one would be;
- **placement only**: the engine service placed as package 2.2's option would place it, in the approved Node image. Not an engine.
