Plain words for the terms used here:
- A **container** is a sealed box a program runs in, with only the files and settings put into it. The **engine container** is the one that writes the app's code; the **runner** is the one that tests the app in a browser.
- The **acceptance store** is the folder where the builder keeps each project's acceptance tests, outside every project's folder. A **version** is one set of those tests; its **manifest** lists each file with its **fingerprint** (SHA-256, a value worked out from the file's bytes).
- A **marker** is a random string put into every test file of a version, so that a search finds any copy of it.
- A **mount** puts a folder of the machine inside a container.
- A **stand-in test** is a test written in advance by Claude Code, allowed by the owner only to develop and test this runner.

## What was built (code, with where)

- **The store**, `builder/src/acceptance/store.ts`: `$BUILDER_DATA_DIR/acceptance/<project>/v001, v002, ...`, refused inside the repository, `builder/`, `templates/` or a sandbox folder (links resolved); a version written under a temporary name and renamed, never written into an existing one; a manifest and a fresh marker in every test file's label line; `verifyVersion` before every run. The version is written **before step 01 runs** (`run-demo.txt`, section 2).
- **The stand-in test**, `stand-in-acceptance/example-1/item-01.spec.ts`, at the top of the repository, a folder no container mounts; written into the store by `builder/src/acceptance/stand-in.ts`, which records `acceptance.version.written` (version, manifest fingerprint, items, `written_by: "stand-in"`; not the marker). "stand-in test" is in its first line, its label line, its test title, the manifest, every event and the screenshots' file names.
- **The runner image**, `builder/runner/` and `builder/src/acceptance/runner-image.ts`: see "The runner image" below.
- **The runner**, `builder/src/acceptance/runner.ts`: checks the version against its manifest and the manifest against its event, checks that the right app answers, runs the runner's container through the sandbox manager, reads the results, then writes `acceptance.run.started`, one `acceptance.item` per item and `acceptance.run.finished` (`events.json`).
- **The result reader**, `builder/src/acceptance/results.ts`: every item starts as "did not run"; "passed" and "failed" only under the design's rules (section 4); the run folder read without following links.
- **The sandbox manager**, `builder/src/sandbox/manager.ts`: the `acceptance` service, under its own profile, refused by `up`; the mount rule (no engine mount of the store's data folder, inside it or above it) in `runStreaming` and `createSandbox`.
- **The broken copy**, `builder/scripted-broken/example-1/03-wrong-status/`, outside `builder/scripted`; its fingerprints chained after step 02 by `builder/scripts/scripted-manifest.ts`.
- **The attempts**, `builder/src/acceptance/probes.ts`; the demonstration, `builder/scripts/demo-acceptance.ts` with `builder/scripts/example-1-sandbox.ts`.
