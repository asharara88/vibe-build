# The sandbox tests' folders in the temporary folder (14 Nov 2026)

**Why:** on 13 Nov, package J1 ran the whole suite with a `TMPDIR` of its own. Its records name `builder-sb-*`, `builder-live-*` "and others" left in it; the task of 14 Nov also named `builder-home-*`, `builder-tools-*` and `builder-user-docker-*`. Removing that `TMPDIR` went with free disk rising from 2.6 GB to 5.8 GB (known gap 137). The folders' own sizes were not measured then.

**Where it ran:** this session's cloud machine, started fresh at 02:52 UTC on 14 Nov. Not the machine J1 measured on. Set-up done by this session, its output not kept: Docker 29.9.2 and PostgreSQL 16 started, the approved browser zip fetched (`scripts/fetch-browser.ts`, exit 0), `npm ci` in `builder/` and, for the licence check, `npm ci --ignore-scripts` in `builder/runner/` (gap 77). No other session's folder was under `/tmp/claude-0/` when listed at the start (output not kept), so the lock (`flock <scratchpad>/live-tests.lock`) had no other holder here; it was taken all the same for every run that starts containers. The typecheck, the licence check, the probes and the failure control start no container and were run without it.

**How:** every run below had a new, empty `TMPDIR` of its own, made by the script, and listed what was left in it afterwards, with `du -sh` for each entry. Scripts: `scripts/run-sandbox-file.sh` (one file), `scripts/run-full-suite.sh` (the whole suite, on a test database made new for the run), `scripts/failure-control.sh`, `scripts/socket-path-probe.js`. The two "first attempt" outputs were made by earlier versions of the first two scripts, which used longer `TMPDIR` names and had no length guard; those versions are not kept (the committed guard refuses such names). The scratchpad's path is written `<scratchpad>` in the outputs.

## The fix

`builder/test/sandbox.test.ts` only (commit `67dcea7`, and `9f65b54` after the review):

- `testFolder(prefix)` makes the folder and registers its removal with vitest's `onTestFinished`, which runs when the test ends, passed or failed (shown by the failure control). Every test in the file that makes a folder now makes it this way: the four that left theirs (seven folders between them), and the five that already removed theirs (three with `onTestFinished`, two in a `finally`), so that one rule covers all.
- `removeFolder(dir)` removes `dir` with everything in it; a folder already gone is not an error. Before that, it opens (mode 700) each folder below `dir` that belongs to the user running the tests, as `test/acceptance-live.test.ts` does in its `afterAll`, so that a read-only folder does not stop the removal; links are neither followed nor changed. *Since `9f65b54`:* another user's folder is left as it is (in `67dcea7` every folder was opened; see "After the review").
- The two live blocks (`builder-live-*`; `builder-tools-*` and `builder-home-*`) already removed their folders in `afterAll`, and did so in every run here. They now do it in a `finally`: before, an error from removing the tools image ended that `afterAll` before its folders were removed.
- **No check changed:** 23 tests and 106 `expect(` calls before and after, no `skip`, `only`, `todo`, `skipIf` or `runIf` in either, and no changed line holds an `expect(` (counted with `grep` on both versions; the review counted again and agreed).

## What this shows, and what it does not

- **Shown:** `sandbox.test.ts` left seven folders, 168 KB, after each run; after the fix it leaves none, with the same command, and a run that does not go through npm leaves `TMPDIR` empty.
- **Shown:** a test that fails still removes its folder (the failure control), where the same failure before the fix left it.
- **Shown:** on this machine, at `14787d8`, those seven were the only folders the whole suite's tests left after a run that ran to its end.
- **Not explained:** the 3.2 GB of 13 Nov. The folders measured here are far too small to account for it. `builder-live-*` and `builder-tools-*`, which J1's records and the task name, are removed by a run that reaches its end; a run stopped part-way is one way to leave them, and here a stopped run also left the runner image's build folder, 115 MB (*inferred, not shown*, for 13 Nov). Other sessions freeing space at the same moment remain possible, as the task said.
- **Designed, not shown:** the live blocks' removal when removing the tools image fails (no run made it fail); and, since `9f65b54`, the removal in a run as a user other than root (every run here was as root).
- **Not done:** `node-compile-cache` (npm's) and `tsx-0` (tsx's, made by the tests that run scripts under it) are left; both are caches that later runs reuse. Folders other test files leave when a run is stopped part-way (such as `builder-runner-build-*`) are not removed by anything.

## Two things found on the way (gap 170)

1. **On a fresh machine the first whole-suite run failed J3's live preview tests.** `test/preview-live.test.ts` needs the runner image `builder-acceptance-runner:local`, which `test/acceptance-live.test.ts` builds. When the preview tests checked (at about 03:10 UTC), Docker answered that no image had that name, and their five tests failed: "the runner image builder-acceptance-runner:local is not on this machine". `docker images` listed the image after that run (output not kept); its own record, read later, says it was created at 03:09:23 UTC, during the stopped first attempt, and last given its name at 03:41:42 UTC, during the run after the fix. Why the name was missing at 03:10 is not known. That the preview file ran before the one that builds the image is *inferred*, not seen in the output: the suite runs one file at a time (`fileParallelism: false`), and with no record of earlier runs vitest 5.1.0 runs larger files first (its own code, `docs/SOURCES.md`); `preview-live.test.ts` is 16,281 bytes and `acceptance-live.test.ts` 13,580. Nothing here was changed for it.
2. **A long `TMPDIR` breaks the suite's tsx scripts.** tsx 4.23.15 makes its socket at `$TMPDIR/tsx-<uid>/<pid>.pipe` (its own code). Node keeps at most 108 bytes of a socket's path and cuts a longer one short without an error (`after-review/socket-path-probe.txt`). With `TMPDIR=<scratchpad>/tmpdir-full-before` (102 bytes), `$TMPDIR/tsx-0` alone is 108 bytes, so every tsx socket path is cut to the name of that folder, which already exists: tsx failed with `EADDRINUSE` (one error, its path printed twice; that path was 119 bytes, for process 21305), and 37 tests failed in six files that run scripts under tsx (overrun, journal-recovery, licence-rule, reconcile, journal-crash, journal-recovery-lock). With `<scratchpad>/fb` (86 bytes) every test in those six files passed. That the cut path caused all 37 is *inferred* from that difference and the one error, not shown test by test. Earlier runs (J1, J3) used `TMPDIR` paths of 93 to 97 bytes and passed. Both scripts here refuse a `TMPDIR` that leaves no room for an 8-digit process number.
