9. **Licence exception for development tools.** The automated check found, among development tools only (never shipped in the builder or in any generated app): `lightningcss` and `lightningcss-linux-x64-gnu` (a CSS processor pulled in by the test runner) under the Mozilla Public License 2.0, a weak copyleft licence under which changes to its own files must be published and nothing else; and `spdx-exceptions` and `spdx-ranges` (licence-name data files used by the licence checker itself) under Creative Commons Attribution 3.0, which asks for credit. Hard rule 2 allows permissive licences only unless the owner approves an exception in writing. (a) **Approve MPL-2.0 and CC-BY-3.0 for development tools that are not shipped.** Recommended; reason: it changes nothing about what customers receive. (b) Replace the test runner and the licence checker to avoid them. Until decided, the check fails only on strong copyleft licences for development tools and prints every other exception, and production dependencies stay strictly permissive.

10. **Licence exception needed for the Django candidate (Decision D).** Django's PostgreSQL support requires the `psycopg` driver, which is under the GNU Lesser General Public License 3.0 (verified from PyPI, 11 Nov 2026). LGPL is a weak copyleft licence: an app may use the library and stay proprietary as long as the library itself is kept separate and replaceable, which is how a Python package is normally installed. But it is not permissive, and the generated apps are installed on customers' infrastructure, so hard rule 2 needs the owner's written exception before the Django template is built. The TypeScript candidate has no such issue: its PostgreSQL driver `pg` is MIT. (a) **Approve LGPL-3.0 for `psycopg` in generated apps**, so both candidates can be measured as the design note says. Recommended; reason: the stack comparison is only meaningful with both candidates built, and LGPL use of an unmodified, separately installed library is the licence's intended case. (b) Drop the Django candidate and build the TypeScript template only. Until decided, the TypeScript template is built first and nothing LGPL is installed.

11. **Licence exception for one data file in generated apps (TypeScript candidate).** Next.js depends on `caniuse-lite`, a table of which browsers support which features, under Creative Commons Attribution 4.0. It is data, not code; the licence asks that credit be given, and nothing else. It ships inside every generated app, so this is not development-only. Hard rule 2 needs the owner's written exception. (a) **Approve CC-BY-4.0 for `caniuse-lite`, with the credit included in each generated app's licence report.** Recommended; reason: every Next.js app in the world carries this file, and the obligation is a line of credit. (b) Decline, which rules out Next.js and most of the TypeScript web ecosystem that uses the same file. Until decided, the template's own licence check stays red on this one package (`evidence/2026-11-11-skeleton-3/next-template.md`).
