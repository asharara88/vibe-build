A *should-fix* point is one a reviewer asked to be fixed but did not rate as blocking a merge; a *note* is a smaller point. No reviewer in any round rated anything blocking.

**Words used here.** A Compose *profile* is a label on a service so that it starts only when asked for by name. A Docker *context* is a saved choice of which Docker installation the `docker` command talks to. A *dry run* only predicts what a command would do, without doing it. `--remove-orphans` tells Compose to remove containers it no longer lists. A *failed promise* is how a program reports a failure that its caller waits for; *throwing at once* reports it before the caller is waiting, which some callers miss. A *bundler comment* is a note that a packaging tool leaves in the code it joins together.

## Round 2: commit `bbe0857`

Three reviewers: the code fixes; a deliberate breach of the new check; the records. **All three: nothing blocking.**

What they ran, in short: the type check, 90 of 90 tests and the licence check passed. The proxy address was in none of the tools image's history, settings or files, on a cached and on a fresh build; a control build with the old Dockerfile had it in 5 history lines. (The daemon's own record of the build still holds it; that is not part of the image.) The check failed, as it should, when a value inside was not the one given, when a builder setting was given under its own name, and when the project's client folder was given proxies. Each new Docker test failed with its fix removed. The Docker client program (29.9.2) was found to contain the names `cliPluginsExtraDirs` and `DOCKER_TLS`. One probe passed that should not have: a made-up builder value given under the name `APP_URL` (the first point below).
