## 4. Stack and running
- **No new dependency.** hono 4.13.17 and @hono/node-server 2.1.6, MIT, already shipped (R package.json:19-20; licences.csv:4, :75). Pages from `hono/html` tagged templates, which escape (R node_modules/hono/package.json:151; the stack reader's run): no JSX, no tsconfig change (I). `csrf()` and `secureHeaders()` on every route (R hono package.json:136, :271), with a content-security-policy of `script-src 'none'` (I).
- **Start.** `npm run web` (`tsx src/web/main.ts`) on 127.0.0.1:4020; the gateway uses 4010 (R src/gateway/main.ts:14, :37). It refuses to start without BUILDER_UI_PASSWORD (12 characters or more), BUILDER_DATA_DIR and BUILDER_DATABASE_URL, as the gateway refuses without its key (R main.ts:9-13). At start it deletes BUILDER_MODEL_API_KEY and BUILDER_UI_PASSWORD from its own environment; Docker already gets a narrow one (R manager.ts:544-550).
- **One instance per database.** It takes a PostgreSQL advisory lock on a connection of its own, as the gateway's liveness lock does (R src/store/liveness.ts:40; src/store/db.ts:19), and refuses to start if it is held. The evidence run and the owner's instance each get their own database and data folder; the default is the shared builder_dev (R db.ts:10) (I).
- **Sign-in** (I): the password kept only as a scrypt digest, compared with `timingSafeEqual`; a session id of 32 random bytes, unsigned, kept in memory with a server-side expiry; cookie HttpOnly, SameSite=Strict, Path=/; sign-out; one guard in front of every route; no GET changes anything; failures limited for the whole server (5, then a lock-out that doubles). Hand-written password handling: a known gap, on the engineer's list, as gap 6 says for apps (R KG:23).
- **Sandboxes.** `makeExample1`, `buildAndStart`, `destroyExample1` and `portFree` unchanged (R example-1-sandbox.ts:56, :127, :141, :44), through a thin adapter `src/orchestrator/example-1-adapter.ts`, moved into src only after 0.6c rewrites them (R M06c:58-78 changes what example-1-sandbox.ts:56-138 does). Project ids start `j1-`, so Compose names start `builder_j1-` (R manager.ts:125-127); J1 removes no Compose project without that prefix (I).
- **Jobs** (I): in the interface process, one at a time, as `journey.job.started/finished/failed/interrupted` events. At start, a project whose last job event is "started" is marked interrupted and its containers and images removed (R manager.ts:751, :734). No resume: `createSandbox` rewrites secrets and fixes the proxy address when called (R manager.ts:456-462, :484-486), and the session proxy's port changes on restart (R M06c:37). The screen offers "Close project" or "New project".
- **Engine events in order** (I): the engine does not wait for the handler's promise (R scripted.ts:193, :207-210) and the pool has 5 connections (R db.ts:15). The handler pushes events onto one queue written by one await chain; `engineFor` returns a wrapper whose `runStep` awaits the queue's drain before returning, so `step.hold_closed` (R src/orchestrator/steps.ts:78-81) follows the step's last event. After a failed step: `resetToLastCommit` (R src/engine/project-repo.ts:252; no caller today, R grep).
- **Languages.** English and Arabic on every screen, the 20 questions included; `lang` and `dir` per page; a test that both message files have the same keys; new Arabic on docs/arabic-wording-list.md (R DEC:26, :80; BP:80; DN:620). Recorded as Claude Code's reading.
- **Disk** (R 13 Nov: `df -h /` showed 533 MB free (99% used), then 1.6 GB (96%); `docker system df`: build cache 16.25 GB, 11.8 GB reclaimable; one project's tools and app images 1.76 GB and 274 MB). Before a build the job refuses below 4 GB free, with a plain message (I: twice the two images); closing a project removes its images (R manager.ts:734).
