# The runner's two base images: packages and notices

**For the owner's question 15** (`docs/QUESTIONS.md`). Read 13 November 2026 by Claude Code, then recounted by a second reader who had not done the first reading. It completes the open items of `runtime-inventory.md` ("`ubuntu:24.04`'s own package list and notices"; "Node's notice in `node:22-bookworm-slim`") with the same method and counting rule, so the figures compare. **It is not a legal reading.** It quotes what the files say and does not say what they require. Nothing here is approved.

Words used here are those of `runtime-inventory.md` (*image*, *digest*, *package*, *notice*, *copyleft*). The *runner* is package 3.1's test container (design note `docs/design/package-3.1.md`); its build file is not written yet. What it takes from each image is read from the build file used to measure 3.1's design on 13 Nov (its line 1 `FROM node:22-bookworm-slim AS node`, lines 19-20).

## How it was read (checked)

- `docker pull` by tag reported the digests above. **Nothing from either image was started**: each was opened with `docker create` (state stayed "created", start time 0001-01-01), its files copied out with `docker export | tar -x` into the session's scratch folder, and the container removed. Docker's event log, read by the second reader, shows only create, export or copy, and remove, with no start, for every container made in this work. No container is left.
- Every file was read as data, by scripts kept outside the extracted files and run with Python in isolated mode (`python3 -I`). Links inside the extracted files were followed only inside that folder. Every extracted file matches the image's own copy (the second reader compared the two file lists, file by file).
- Each package's `/usr/share/doc/<package>/copyright` was read. Where a doc folder is a link to another package's (`libgcc-s1` and `libstdc++6` to `gcc-14-base` or `gcc-12-base`; in `ubuntu:24.04` also `libncursesw6` to `libtinfo6`), the linked file is the one read.
- **Calibration.** Before counting, both readers' code and the second reader's own were run on the inventory's 84 stored Ubuntu texts (`raw/ubuntu-copyright/`). Each gave the inventory's figures exactly: 188 `License:` values as written, 142 after splitting alone, 131 single names.

## 3. The counting rule used, and the four differences the second reader found

The second reader recounted both images independently and found four differences between its recount and the first readers'. Each is settled here by stating the rule used; every figure in this file follows it.

1. **Splitting licence values.** The two first readers used different rules, though both reported "111 single names": the `ubuntu:24.04` reader also split values at "and/or"; the `node:22-bookworm-slim` reader did not. Two values are affected, and both are in both images: "BSD-3-clause and/or GPL-3+" and "ISC and/or LGPL-2.1+". **Rule used: the inventory's, as written** (`runtime-inventory.md`, section 2): each value is split at the words "and" and "or" (in any letter case) and at commas, brackets are removed, and letter case is ignored. "and/or" is neither word, so those two values stay one name each (both are counted as copyleft names). Under it: `ubuntu:24.04` 148 / 118 / 113 (41 copyleft, 6 permitted, 66 neither; 75 not among the 119's 131; with the 119, 297 values and 206 names); `node:22-bookworm-slim` 143 / 116 / 111 (39, 6, 66; 75 not among the 131). For comparison only, splitting at "and/or" as well gives 148 / 116 / 111 and 143 / 114 / 109, with 39 and 37 copyleft names. The two copyleft figures differ only by those two combined names.
2. **The two keyring packages.** `ubuntu-keyring` was counted with a copyleft main entry, `debian-archive-keyring` without, though both files say the same thing: "The keys in the keyrings don't fall under any copyright. Everything else in the package is covered by the GNU GPL", GPL version 2 or later. **Rule used:** for a hand-read file, the main entry is copyleft when the file puts any of the package under a copyleft licence and states no other licence for the rest; text it says falls under no copyright is not counted either way. Both keyrings are therefore counted as copyleft: `ubuntu:24.04` 70, `node:22-bookworm-slim` 67. The one cell changed for this from the first reader's table is `debian-archive-keyring`'s in `raw/node-22-bookworm-slim-packages.tsv`, marked in the cell. Counting neither would give 69 and 66. Apart from this, both main-entry lists match the second reader's package for package.
3. **An empty `License:` field.** `liblzma5`'s header paragraph has a `License:` field with no name in it (explanatory text follows). Both readers left it out without saying so. **Rule used:** a `License:` field with no name is not counted as a value. Counting it gives 149 and 144 values as written; the single-name figures do not change. The 119 had no such field, so their figures are unaffected.
4. **Two line references.** The `ubuntu:24.04` reader cited `docs/SOURCES.md` lines 134 (the digest) and 139 (the download stage). They are lines 146 and 151 at the commit this file was written from; the quoted content was correct. This file cites `docs/SOURCES.md` by its section and wording, not by line.

Everything else the second reader recounted matched: the package counts and architectures; every copyright file present, with the linked ones; 66 and 63 distinct texts; 81 and 74 machine-readable, 11 (8 texts) and 14 (10 texts) free text; 84 and 80 name a copyleft licence somewhere, with the same two lists of 8; the letters "GPL" in 84 and 80 files; the 11 choices in each; the stored texts; the operating system versions; the quotations; Node's version, notice and program fingerprints; the npm, yarn and corepack licence files; npm's 1,964 files; and `docs/design/package-3.1.md` line 34, which plans "both base images pinned by digest".
