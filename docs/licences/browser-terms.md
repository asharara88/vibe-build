## 1. Which terms apply, and why

1. **`ABOUT`** says: "Google Chrome / Copyright 2026 Google LLC. All rights reserved. / Chrome is made possible by the Chromium open source project (https://www.chromium.org/) and other open source software (chrome://credits). / See the Terms of Service at chrome://terms."

It was read from copies of the resource files; no program from the browser folders was started. Title: "Google Chrome and ChromeOS Additional Terms of Service"; "Last modified: September 30, 2025". 52 of the 55 base locale files carry it (af, ms and ur do not). Its first sentence brings in Google's general terms: "By using Chrome or ChromeOS, you agree to the Google Terms of Service located at https://policies.google.com/terms and these Google Chrome and ChromeOS Additional Terms of Service." Inferred from a string search only: the headless shell probably does not serve a `chrome://terms` page (its program has no such string); this does not matter, since the text is in the zip's own files and online.
3. **Google's list of services** (`policies.google.com/terms/service-specific`) puts "Chrome and ChromeOS" under "Terms of Service" plus "Google Chrome and ChromeOS Additional Terms of Service". The same page says: "Most of our fee-based enterprise products and our developer API products have their own terms as well."
4. **No terms specific to Chrome for Testing were found.** Six developer.chrome.com pages about it end with: "Except as otherwise noted, the content of this page is licensed under the Creative Commons Attribution 4.0 License, and code samples are licensed under the Apache 2.0 License. For details, see the Google Developers Site Policies." By its words this covers the pages and code samples, not the browser builds. The Google Developers Site Policies page was **not read** (its host is not on the session's allowed list). The Chrome for Testing code repository's own licence is Apache 2.0, and nothing read says it covers the builds (inventory). The build names itself "Google Chrome" and ships Chrome's own additional terms. **Inferred:** it is under Chrome's ordinary terms, with the caveat of point 3.

So the set that applies is:

- **(C)** The open-source licences in `LICENSE.headless_shell` (295 sections), for the parts they cover. (A): "Most source code for Chrome is available free of charge under open source software license agreements at chrome://credits." ## 4. FFmpeg's optional GPL parts

**What the files show (checked).** The FFmpeg section of `LICENSE.headless_shell` (lines 8790-9786) is FFmpeg's generic upstream statement, not a record of this build's options: "In combination the LGPL v2.1+ applies to FFmpeg." Then (lines 8799-8802): "Some optional parts of FFmpeg are licensed under the GNU General Public License version 2 or later (GPL v2+). See the file `COPYING.GPLv2` for details. None of these parts are used by default, you have to explicitly pass `--enable-gpl` to configure to activate them." It lists the GPL parts (three x86 files, six build and test tools, 33 filters; one, `vf_lensfun.c`, "(GPL version 3 or later)", line 8831), 12 per-file notices, none copyleft, and the full LGPL 2.1 text from line 9285. No GPL text is in the section. The zip has no separate FFmpeg library (its only shared libraries are `libEGL.so`, `libGLESv2.so`, `libvk_swiftshader.so` and `libvulkan.so.1`); FFmpeg is built into the program, which contains "FFmpegDemuxer", "FFmpegVideoDecoder" and "FFmpegAudioDecoder". Searched in the program's bytes (not run): "--enable-gpl" 0, "avfilter" 0, "flac_enc" 0, none of the 33 GPL filter names as a filter name, and no FFmpeg licence string.

**Conclusion.** No sign of the GPL filters. The GPL x86 files are **not established** either way: FFmpeg builds them only when GPL is enabled, and a stripped program keeps no file names. What would settle it: Chromium's FFmpeg build settings for this version, whose host is not reachable from this session.

**Does it matter for internal use? The licences' own words** (GPL texts from `/usr/share/common-licenses/` on the development machine):

- GPL 2.0, section 0, and LGPL 2.1, section 0: "Activities other than copying, distribution and modification are not covered by this License; they are outside its scope. The act of running the Program is not restricted" (LGPL: "running a program using the Library"). So copying is within their scope; what they leave unrestricted is running.
- GPL 3.0, section 2: "This License explicitly affirms your unlimited permission to run the unmodified Program." and "You may make, run and propagate covered works that you do not convey, without conditions so long as your license otherwise remains in force." Its definition: "To 'convey' a work means any kind of propagation that enables other parties to make or receive copies. Mere interaction with a user through a computer network, with no transfer of a copy, is not conveying."

Plain reading: FFmpeg's GPL parts are "version 2 or later" (and `vf_lensfun.c` "version 3 or later"), so they may be taken under version 3, whose section 2 expressly allows making and running copies that are not passed on, without conditions. The duties these licences write down attach to passing copies on (or changing them). The FFmpeg question would matter only if copies were passed on, which condition 2 rules out.
